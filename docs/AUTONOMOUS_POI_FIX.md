# 自动经停搜索修复

## 问题与修复

页面将“经过一家面包店买面包”提取成 `poi_name="bakery"`，而原有类别仅有咖啡店、餐厅和医院，导致模型去地理编码泛指类别，再要求用户选择具体门店。

新增 `bakery` 类别，明确 `poi_name` 只用于用户实际指定的门店名称。泛指类别作为具体店名时，后端要求模型修正提取；类别需求不能通过 `resolve_place` 或 `ask_user` 转成指定门店确认。

Agent 可调用 `search_pois` 自主搜索类别或具体名称。默认围绕已取得的真实 OSRM 参考路线，最多采样五个服务返回的路线顶点，一次 Overpass 查询搜索候选；仍可根据结果决定搜索起点或终点附近。采样范围有限，不能声称穷尽所有沿途门店。候选的粗略距离筛选不代替 OSRM 分段算路，也不验证到达时限。

面包店查询使用 OpenStreetMap 的 [`shop=bakery`](https://wiki.openstreetmap.org/wiki/Tag%3Ashop%3Dbakery) 标签，查询组合遵循官方 [Overpass QL](https://wiki.openstreetmap.org/wiki/Overpass_API/Overpass_QL)。保留真实 OSM 身份、位置及营业标签，不用咖啡店冒充面包店。

工具返回多个候选后，LLM 决定规划哪些门店，后端计算和验证实际路线。单个门店返回无路线时继续其他候选；网络、认证等服务错误仍如实报告。首批查询为空或候选验证失败时允许扩大搜索，保持有限预算和原始约束。

买面包预计停留多久、家庭／公司确切位置、是否有车等无法得知的个人事实仍需要确认。系统不会从出发到到达的剩余时间推断购物时长。公共交通业务经停仍是已有的能力限制，本次没有声称解决。

## 验证

- 浏览器重试用户原文，页面只询问缺失的停留时间，并显示“由系统选择沿途面包店”，不再要求门店地址。
- 真实地图测试：Raffles City 至 Marina Bay Sands 的 OSRM 步行参考路线约 1.96 公里，Overpass 返回十个真实面包店候选。此为公共地标测试，不是替用户确认家庭／公司位置。
- 真实 Agent 测试记录 `outputs/20261005T095106-e18f457b/result.json`：提供已核实的公共地标地点 ID，要求步行、沿途买面包、停留五分钟、一小时内到达；模型自主搜索十个面包店，计算二十二条候选，通过验证和比较选择 Paris Baguette 方案，服务预计约三十一分钟，全程没有门店确认问题。耗时约九十一秒；模型曾出现两次不符合当前状态的工具调用，经后端反馈后继续完成。单个测试不证明所有需求或实时条件均可满足。
- 回归测试覆盖泛指与店名的区分、真实标签、参考路线证据、沿途采样、自动比较多个门店、到达检查、无法算路门店、首批空结果及营业失败后的重新搜索和重规划。

项目长期目标见 [PROJECT_GOALS.md](PROJECT_GOALS.md)，保持 Agent 的自主决策，避免针对示例固定所有工具调用。
