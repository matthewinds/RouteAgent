# DeepSeek 收尾超時與 OneMap 票價缺失修復

2026-10-10 的 `20261010T123631-ad70f7ea` 規劃已成功調用模型 12 次；第 13 次在 230.618 秒開始，總預算為 240 秒。單次候選搜索耗時 132.4 秒。舊代碼將所有模型異常改寫為檢查 Key／模型／餘額／網絡，未保留原異常類型，因此只能從時序推斷最後一次很可能超時，不能追溯確認原始異常。

## 修改

- OneMap 真實響應中的 `fare: "info unavailable"` 表示票價未知。保留通過原有幾何、端點、換乘與時序檢查的行程；不填造票價，不支持據此聲稱最便宜。其他無效數字仍拒絕。
- 每個方式的候選搜索批次預算為 45 秒，總預算仍為 240 秒；預留 60 秒與 16 次外部請求用於票價、核驗、比較和模型完成推薦。批次範圍內的路線請求、重試和請求間隔共用邊界，已完成候選保留，有限搜索明確記錄。這是搜索預算，不是服務全程絕對耗時保證。
- 各輪將剩餘時間、請求與模型輪數提供給 LLM，要求及時完成已有候選的核驗及推薦。預算信息加在最新結果中，保留穩定的系統及歷史前綴。後端不代替 LLM 選路，不放寬硬約束或證據要求。
- 進入預留階段後停止新增門店／站點搜索；新方式的規劃請求仍記錄預算邊界，避免把未完成比較冒充全部方式比較成功。
- 模型錯誤分別標註超時、總預算耗盡、連接、鑑權、餘額及限流。保存異常類型、HTTP 狀態、輪數與超時預算；不保存原始異常消息、響應體或憑據。

配置位於 `src/route_agent/config.py`。修改後重啟 PyCharm 的 **FYP Web**，再提交需求；刷新配置狀態只重讀 `.env`。

## 驗證與限制

新增測試覆蓋票價缺失、錯誤分類與憑據保護、搜索重試共用預算、保留已完成候選、預留階段核驗和有限方式比較。完整測試集通過。

使用該次失敗保存的真實 OneMap 響應做離線回放，原先被拒絕的起終點公共交通查詢現在保留 3 條行程，票價全部保持未知，未發送網絡請求。結果見 `outputs/bug-diagnostics/deepseek-budget-fix-replay.json`。

離線回放與模擬測試不代表修復後的 DeepSeek 全程在線验收；網絡、實時服務和模型決策仍可能導致超時或證據不足，屆時必須如實報告。
