# FYP 五阶段 Agent 架构与实施核对

更新：2026-10-02。以用户本次给出的五个步骤为目标，区分目标能力、已实现代码与真实验收。模块进度见 [FYP_IMPLEMENTATION_PLAN.md](FYP_IMPLEMENTATION_PLAN.md)。

## 核心目标

用户在网页输入自然语言出行需求，DeepSeek 读取需求和工具反馈，自主决定下一次查询、候选生成策略、澄清或重规划。地图工具计算路径，后端计算指标并检查约束，模型从通过检查的候选中选择并解释。未知证据不能由模型补造。

五个阶段是职责划分，不是固定的五次调用。模型可以先查 POI 再算路，也可以先算路再查沿途天气；可以在验证后补充信息，再次验证。只为用户要求或具体不确定性调用工具。

## 信息查询决策规则

查询规则约束证据完整性，具体调用顺序由模型决定。

| 用户要求或信息缺口 | 对应查询 | 缺证据时的行为 |
| --- | --- | --- |
| 起终点未定位／地点歧义 | 地点解析；必要时请用户选地点 | 不自行猜测地点 |
| 咖啡店、医院、餐厅或指定经停 | OSM POI；要求营业时查询营业信息 | 不创建虚构 POI；营业未知单列 |
| 需要道路标签作判断 | OSM 道路查询 | 标签缺失保持未知；不把查询当作路由计算 |
| 驾车有总时间上限、到达时限、避堵要求／偏好，或需要到店时段检查 | LTA 交通查询 | 必须尝试查询；完整性不足不能证明硬时限或避堵达标 |
| 查询天气、希望避雨或要求不淋雨 | Open-Meteo；NEA 可选补充 | 必须尝试查询；预报不能保证全程不淋雨 |
| 驾车后停车步行 | 停车点、当前车位、驾车与步行路径 | 不保证到达时有位；停车预留及实际转换点需要用户确认 |
| 普通步行，没有天气要求 | 模型可只定位、算路、验证和比较 | 不因“步行”强制调用天气 |
| 普通驾车，没有时间或拥堵要求 | 模型决定是否补查交通 | 可展示 OSRM 基础服务时间；没有交通证据不能称为实时 ETA |

本轮已移除“所有步行必须查询天气”和“所有驾车必须查询交通”的固定要求；仍保留相关需求的必需查询与发布验证。模型主动选择额外查询时，返回的数据也必须按来源和有效期处理。

## 候选策略的目标与当前差距

目标是让模型显式选择最快、最短、避高速或经停策略，并让路由工具返回策略、引擎、参数、几何及指标证据。模型不能自己画线、估算距离、修改服务耗时或声称有限搜索找到了全局最优。

当前正常入口使用 ORS／Pelias 定位、OSRM 算路；OSM Overpass 已提供道路与 POI。OSRM 默认替代路径和用户硬性避高速参数已有代码，但当前公共实例不支持 motorway 排除； `plan_candidates` 尚未提供最快／最短／避高速的独立策略参数。软性避高速评分无法代替主动生成该类候选。

用户后续选择 OSRM；现已完成真实 OSRM Route 适配和 car／foot 查询验证。OSMnx 不作为正常路由引擎；地址定位仍为 ORS，算路没有 ORS 回退。

后续候选模块应按以下顺序推进：

1. 统一路由请求／返回协议，包含策略、引擎、分段方式及证据；保留真实服务原始指标。
2. 给 `plan_candidates` 增加策略参数，硬约束始终生效；不支持的策略明确报错，不能退回默认路线后标成已支持。
3. 缓存键与重规划签名包含策略，允许同一 POI 在验证失败后换策略；相同路径去重并保留来源。
4. OSRM car／foot 适配及真实基础路线查询已完成；为避高速和批量实验配置并验收自建或获授权实例。公共端点的基础响应不代表所有策略可用。
5. 用真实路线验证最快／最短／避高速／经停候选的行为，记录服务限制和有限搜索范围。

## 闭环案例与验收

示例：“从 A 到 B，30 分钟内到达，希望避堵，并经过一家咖啡店。”未指定方式时先比较真实步行／驾车参考路线，由模型选择；未指定出发时间按现在；咖啡店停留时间等必要信息缺失时在页面澄清。

模型提交结构化需求 → 定位 A／B → 查询真实咖啡店 → 生成候选与查询必要交通 → 检查包含停留的总时间及 POI → 读取失败或未知原因 → 选择另一个真实 POI、不同策略或扩大范围 → 再算路、再验证 → 比较通过的路线并选择。

如果只是缺交通证据，不能声称换一条路已解决时限问题；若只是预报缺失，也不能把“未知”改成“无雨”。只有硬约束均通过才正式推荐。最多重规划两次，不放宽用户硬约束；无解仅表示当前有限范围内未找到。

必须保留请求、每次工具参数、调用 ID、候选、验证原因、重规划决策所对应的工具动作、证据及最终选择。页面展示简短进度与检查依据，不公开原始思考链。

## 本轮核对与剩余验收

- 已落实：按需求要求交通／天气查询；无关查询不强制执行；相关硬约束证据规则继续有效。
- 自动化：121 项通过，包含按需调用、OSRM 协议、错误分类、自动方式与输入及分页边界检查；模拟返回不能代表真实 API 接通。
- 独立真实证据：OSRM 驾车／步行见 [OSRM_API_EVIDENCE.json](OSRM_API_EVIDENCE.json)；OSM 道路／医院／餐厅、Open-Meteo 天气；详情见 [OSM_WEATHER_API_EVIDENCE.json](OSM_WEATHER_API_EVIDENCE.json)。

## 2026-10-02 自然语言入口与真实个案

首页只输入自己的需求；DeepSeek 提取明确方式，未明确时调用 compare_modes／choose_mode，引用真实 OSRM 路线证据。原文未来出发时间不由初始表单覆盖。网页分开显示基础总时长和交通修正总时长。

真实模型已通过一个自动选择步行、推荐、地图和下载流程。真实 LTA 已读取 76 页并保留部分数据，两条路线约 63%／74% 覆盖；这不代表完整实时 ETA。细节、限制及证据见 [FREE_TEXT_AND_TRAFFIC_FIX.md](FREE_TEXT_AND_TRAFFIC_FIX.md)。
