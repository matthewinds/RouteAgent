# FYP 五階段 Agent 架構與實施核對

更新：2026-10-02。以用戶本次給出的五個步驟為目標，區分目標能力、已實現代碼與真實驗收。模塊進度見 [FYP_IMPLEMENTATION_PLAN.md](FYP_IMPLEMENTATION_PLAN.md)。

## 核心目標

用戶在網頁輸入自然語言出行需求，DeepSeek 讀取需求和工具反饋，自主決定下一次查詢、候選生成策略、澄清或重規劃。地圖工具計算路徑，後端計算指標並檢查約束，模型從通過檢查的候選中選擇並解釋。未知證據不能由模型補造。

五個階段是職責劃分，不是固定的五次調用。模型可以先查 POI 再算路，也可以先算路再查沿途天氣；可以在驗證後補充信息，再次驗證。只為用戶要求或具體不確定性調用工具。

## 信息查詢決策規則

查詢規則約束證據完整性，具體調用順序由模型決定。

| 用戶要求或信息缺口 | 對應查詢 | 缺證據時的行為 |
| --- | --- | --- |
| 起終點未定位／地點歧義 | 地點解析；必要時請用戶選地點 | 不自行猜測地點 |
| 咖啡店、醫院、餐廳或指定經停 | OSM POI；要求營業時查詢營業信息 | 不創建虛構 POI；營業未知單列 |
| 需要道路標籤作判斷 | OSM 道路查詢 | 標籤缺失保持未知；不把查詢當作路由計算 |
| 駕車有總時間上限、到達時限、避堵要求／偏好，或需要到店時段檢查 | LTA 交通查詢 | 必須嘗試查詢；完整性不足不能證明硬時限或避堵達標 |
| 查詢天氣、希望避雨或要求不淋雨 | Open-Meteo；NEA 可選補充 | 必須嘗試查詢；預報不能保證全程不淋雨 |
| 駕車後停車步行 | 停車點、當前車位、駕車與步行路徑 | 不保證到達時有位；停車預留及實際轉換點需要用戶確認 |
| 普通步行，沒有天氣要求 | 模型可只定位、算路、驗證和比較 | 不因“步行”強制調用天氣 |
| 普通駕車，沒有時間或擁堵要求 | 模型決定是否補查交通 | 可展示 OSRM 基礎服務時間；沒有交通證據不能稱為實時 ETA |

本輪已移除“所有步行必須查詢天氣”和“所有駕車必須查詢交通”的固定要求；仍保留相關需求的必需查詢與發佈驗證。模型主動選擇額外查詢時，返回的數據也必須按來源和有效期處理。

## 候選策略的目標與當前差距

目標是讓模型顯式選擇最快、最短、避高速或經停策略，並讓路由工具返回策略、引擎、參數、幾何及指標證據。模型不能自己畫線、估算距離、修改服務耗時或聲稱有限搜索找到了全局最優。

當前正常入口使用 ORS／Pelias 定位、OSRM 算路；OSM Overpass 已提供道路與 POI。OSRM 默認替代路徑和用戶硬性避高速參數已有代碼，但當前公共實例不支持 motorway 排除； `plan_candidates` 尚未提供最快／最短／避高速的獨立策略參數。軟性避高速評分無法代替主動生成該類候選。

用戶後續選擇 OSRM；現已完成真實 OSRM Route 適配和 car／foot 查詢驗證。OSMnx 不作為正常路由引擎；地址定位仍為 ORS，算路沒有 ORS 回退。

後續候選模塊應按以下順序推進：

1. 統一路由請求／返回協議，包含策略、引擎、分段方式及證據；保留真實服務原始指標。
2. 給 `plan_candidates` 增加策略參數，硬約束始終生效；不支持的策略明確報錯，不能退回默認路線後標成已支持。
3. 緩存鍵與重規劃簽名包含策略，允許同一 POI 在驗證失敗後換策略；相同路徑去重並保留來源。
4. OSRM car／foot 適配及真實基礎路線查詢已完成；為避高速和批量實驗配置並驗收自建或獲授權實例。公共端點的基礎響應不代表所有策略可用。
5. 用真實路線驗證最快／最短／避高速／經停候選的行為，記錄服務限制和有限搜索範圍。

## 閉環案例與驗收

示例：“從 A 到 B，30 分鐘內到達，希望避堵，並經過一家咖啡店。”未指定方式時先比較真實步行／駕車參考路線，由模型選擇；未指定出發時間按現在；咖啡店停留時間等必要信息缺失時在頁面澄清。

模型提交結構化需求 → 定位 A／B → 查詢真實咖啡店 → 生成候選與查詢必要交通 → 檢查包含停留的總時間及 POI → 讀取失敗或未知原因 → 選擇另一個真實 POI、不同策略或擴大範圍 → 再算路、再驗證 → 比較通過的路線並選擇。

如果只是缺交通證據，不能聲稱換一條路已解決時限問題；若只是預報缺失，也不能把“未知”改成“無雨”。只有硬約束均通過才正式推薦。最多重規劃兩次，不放寬用戶硬約束；無解僅表示當前有限範圍內未找到。

必須保留請求、每次工具參數、調用 ID、候選、驗證原因、重規劃決策所對應的工具動作、證據及最終選擇。頁面展示簡短進度與檢查依據，不公開原始思考鏈。

## 2026-10-02 自然語言入口與真實個案

首頁只輸入自己的需求；DeepSeek 提取明確方式，未明確時調用 compare_modes／choose_mode，引用真實 OSRM 路線證據。原文未來出發時間不由初始表單覆蓋。網頁分開顯示基礎總時長和交通修正總時長。

真實模型已通過一個自動選擇步行、推薦、地圖和下載流程。真實 LTA 已讀取 76 頁並保留部分數據，兩條路線約 63%／74% 覆蓋；這不代表完整實時 ETA。細節、限制及證據見 [FREE_TEXT_AND_TRAFFIC_FIX.md](FREE_TEXT_AND_TRAFFIC_FIX.md)。
