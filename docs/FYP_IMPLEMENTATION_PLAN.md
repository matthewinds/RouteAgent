## 最終目標和流程

按用戶確認的五階段架構推進：理解需求 → 自主查詢信息 → 生成候選 → 驗證與重規劃 → 排序並解釋。職責、按需查詢規則、OSRM 適配與多策略現狀見 [FYP_AGENT_ARCHITECTURE.md](FYP_AGENT_ARCHITECTURE.md)。五階段不是固定工具調用順序。

用戶在瀏覽器輸入需求 → DeepSeek 思考並選擇真實工具 → 讀取返回證據繼續查詢／有限重規劃 → 後端檢查硬約束和引用 → 模型選擇通過檢查的候選 → 網頁顯示地圖、分段行程、推薦說明、未知條件和記錄下載。

模型固定為官方 `deepseek-flash`，開啟思考和原生工具調用。工具：ORS/Pelias 地址；OSM Overpass 道路／POI／營業信息；OSRM 駕車與步行 Route；LTA 路況／事故／車位；Open-Meteo 小時網格天氣／NEA 區域補充；確定性檢查／比較／澄清／提交結果。

## 接口與數據

`plan_route(text, clarifications=None, *, settings=None, progress=None) -> PlanningResult`

網頁不直接算路。設置與密鑰只留後端；結果包含狀態、TravelRequest、真實 RouteLeg、GeoJSON、硬約束檢查、推薦與最多兩條備選、待核實方案、Evidence、工具事件、預算和指標。導出標記 schema_version=2。舊版 JSON 作為歷史文件保存，當前入口不執行舊記錄。

模型使用後端返回的地點／候選／證據 ID，不能創建路線指標或放寬硬約束。最終數字、地點名和天氣事實由驗證結果回填；頁面展示簡短階段與依據，原始 reasoning_content 不進頁面／日誌／導出。

## 三種出行方式

- 駕車：OSRM car 實例，基礎時間明確是非實時交通時間。
- 全程步行：OSRM foot 實例，可有一個經停，累計所有步行段、經停時間和距離；交通覆蓋顯示“不適用”。
- 駕車後步行：起點駕車 → 停車點 → 步行經停／終點；最多一次轉換。LTA 當前車位和用戶指定停車點均可使用。未知轉換入口待用戶確認，不畫虛構連接。停車預留由用戶填寫；缺失時澄清。

總時間包含全部行駛／步行、業務經停和停車預留。OSRM 分段入口差超過 2 米時連接保持待核實，不添加零耗時連接。現實門口到路網的可達性仍需真實檢查。

Open-Meteo 為已查詢路線選取最多 8 個座標，返回小時降水概率、降水量和天氣代碼；按整個行程時段保守關聯採樣點，不推造逐點到達時間。NEA 兩小時區域預報可顯式查詢為補充。“希望避雨”參與比較，“保證全程不淋雨”保持未知。超出預報有效期或駕車總時間未知時，不斷言預報覆蓋完整行程。

## 證據和限制

- LTA 按方向、幾何重疊和可用道路名匹配；未覆蓋部分保持未知，不填本地默認車速。完整覆蓋才顯示完整駕車服務時間估計。
- 硬到達時限需要有效交通區間；未來計劃出發不能直接用當前路況證明準時（僅為即時提交容許一分鐘時鐘誤差）。事故未可靠匹配不能認定封路。
- POI 首輪 10，失敗後可擴大到 30；每段最多 3 替代路徑；每輪最多 10 個設施組合，僅啟發式排序並顯式記錄截斷。
- 初次規劃後最多重規劃兩次；驗證失敗才擴大，不自行降低硬約束。搜索失敗只表示本次有限範圍內未找到。
- 所有硬約束通過才正式推薦；未知方案另列。停車“當前有位”不等於未來有位。
- 默認時間 0.7、距離 0.2、不確定性 0.1；避堵時 0.5／0.1／擁堵 0.3／不確定性 0.1。避雨偏好另分配 0.2 給天氣參考，其餘同比縮放。Open-Meteo 比較值採用採樣點及行程小時內最大降水概率，不稱為整程淋雨概率；空間採樣不增加模型分辨率。
- 每次最多 16 輪模型交互、32 工具執行、96 HTTP 請求、240 秒總預算；分頁、重試和模型調用均計入。網絡請求設超時，臨時錯誤／429 最多重試兩次。
- 真實緩存保留來源、原獲取時間和有效期；新請求拒絕過期緩存。交通、車位在發佈時再次檢查有效性。
- API Key 和認證頭不進入模型、導出、事件、錯誤內容或頁面；異常診斷只保存類型和代碼位置。

## 網頁功能與驗收

網頁僅要求輸入自然語言需求，取消示例、預填需求和初始方式／時間選擇；方式未指定時由模型比較工具結果再判斷，未指定出發時間按提交時刻。頁面保留必要澄清、模型與工具進度、候選比較、駕車實線／步行虛線、停車轉換點、天氣採樣表、OSM 道路標籤、車位、逐項檢查、失敗／未知提示、修改提交和 JSON 下載。後臺任務保持頁面可交互；配置狀態只判斷填寫情況。

憑據齊全後的真實驗收：

1. 駕車正常推薦和真實地圖，人工抽檢 LTA 方向／覆蓋。
2. 全程步行；有天氣要求時展示有效 Open-Meteo 預報，NEA 為可選補充。
3. 缺信息後在頁面澄清並繼續。
4. 首批候選失敗，模型擴大真實查詢並恢復。
5. 時間／營業／天氣證據不足時保持待核實，有限無解解釋準確。
6. 接駁模式：停車預留、車位、實際入口、駕車／步行幾何及總時間。
7. 修改條件後重新提交，並下載不含憑據的 v2 記錄。
8. 錯誤 Key、額度不足和網絡錯誤顯示明確提示，無舊結果替代。
