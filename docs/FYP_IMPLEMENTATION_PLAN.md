## 最终目标和流程

按用户确认的五阶段架构推进：理解需求 → 自主查询信息 → 生成候选 → 验证与重规划 → 排序并解释。职责、按需查询规则、OSRM 适配与多策略现状见 [FYP_AGENT_ARCHITECTURE.md](FYP_AGENT_ARCHITECTURE.md)。五阶段不是固定工具调用顺序。

用户在浏览器输入需求 → DeepSeek 思考并选择真实工具 → 读取返回证据继续查询／有限重规划 → 后端检查硬约束和引用 → 模型选择通过检查的候选 → 网页显示地图、分段行程、推荐说明、未知条件和记录下载。

模型固定为官方 `deepseek-flash`，开启思考和原生工具调用。工具：ORS/Pelias 地址；OSM Overpass 道路／POI／营业信息；OSRM 驾车与步行 Route；LTA 路况／事故／车位；Open-Meteo 小时网格天气／NEA 区域补充；确定性检查／比较／澄清／提交结果。

## 接口与数据

`plan_route(text, clarifications=None, *, settings=None, progress=None) -> PlanningResult`

网页不直接算路。设置与密钥只留后端；结果包含状态、TravelRequest、真实 RouteLeg、GeoJSON、硬约束检查、推荐与最多两条备选、待核实方案、Evidence、工具事件、预算和指标。导出标记 schema_version=2。旧版 JSON 作为历史文件保存，当前入口不执行旧记录。

模型使用后端返回的地点／候选／证据 ID，不能创建路线指标或放宽硬约束。最终数字、地点名和天气事实由验证结果回填；页面展示简短阶段与依据，原始 reasoning_content 不进页面／日志／导出。

## 三种出行方式

- 驾车：OSRM car 实例，基础时间明确是非实时交通时间。
- 全程步行：OSRM foot 实例，可有一个经停，累计所有步行段、经停时间和距离；交通覆盖显示“不适用”。
- 驾车后步行：起点驾车 → 停车点 → 步行经停／终点；最多一次转换。LTA 当前车位和用户指定停车点均可使用。未知转换入口待用户确认，不画虚构连接。停车预留由用户填写；缺失时澄清。

总时间包含全部行驶／步行、业务经停和停车预留。OSRM 分段入口差超过 2 米时连接保持待核实，不添加零耗时连接。现实门口到路网的可达性仍需真实检查。

Open-Meteo 为已查询路线选取最多 8 个坐标，返回小时降水概率、降水量和天气代码；按整个行程时段保守关联采样点，不推造逐点到达时间。NEA 两小时区域预报可显式查询为补充。“希望避雨”参与比较，“保证全程不淋雨”保持未知。超出预报有效期或驾车总时间未知时，不断言预报覆盖完整行程。

## 证据和限制

- LTA 按方向、几何重叠和可用道路名匹配；未覆盖部分保持未知，不填本地默认车速。完整覆盖才显示完整驾车服务时间估计。
- 硬到达时限需要有效交通区间；未来计划出发不能直接用当前路况证明准时（仅为即时提交容许一分钟时钟误差）。事故未可靠匹配不能认定封路。
- POI 首轮 10，失败后可扩大到 30；每段最多 3 替代路径；每轮最多 10 个设施组合，仅启发式排序并显式记录截断。
- 初次规划后最多重规划两次；验证失败才扩大，不自行降低硬约束。搜索失败只表示本次有限范围内未找到。
- 所有硬约束通过才正式推荐；未知方案另列。停车“当前有位”不等于未来有位。
- 默认时间 0.7、距离 0.2、不确定性 0.1；避堵时 0.5／0.1／拥堵 0.3／不确定性 0.1。避雨偏好另分配 0.2 给天气参考，其余同比缩放。Open-Meteo 比较值采用采样点及行程小时内最大降水概率，不称为整程淋雨概率；空间采样不增加模型分辨率。
- 每次最多 16 轮模型交互、32 工具执行、96 HTTP 请求、240 秒总预算；分页、重试和模型调用均计入。网络请求设超时，临时错误／429 最多重试两次。
- 真实缓存保留来源、原获取时间和有效期；新请求拒绝过期缓存。交通、车位在发布时再次检查有效性。
- API Key 和认证头不进入模型、导出、事件、错误内容或页面；异常诊断只保存类型和代码位置。

## 网页功能与验收

网页仅要求输入自然语言需求，取消示例、预填需求和初始方式／时间选择；方式未指定时由模型比较工具结果再判断，未指定出发时间按提交时刻。页面保留必要澄清、模型与工具进度、候选比较、驾车实线／步行虚线、停车转换点、天气采样表、OSM 道路标签、车位、逐项检查、失败／未知提示、修改提交和 JSON 下载。后台任务保持页面可交互；配置状态只判断填写情况。

凭据齐全后的真实验收：

1. 驾车正常推荐和真实地图，人工抽检 LTA 方向／覆盖。
2. 全程步行；有天气要求时展示有效 Open-Meteo 预报，NEA 为可选补充。
3. 缺信息后在页面澄清并继续。
4. 首批候选失败，模型扩大真实查询并恢复。
5. 时间／营业／天气证据不足时保持待核实，有限无解解释准确。
6. 接驳模式：停车预留、车位、实际入口、驾车／步行几何及总时间。
7. 修改条件后重新提交，并下载不含凭据的 v2 记录。
8. 错误 Key、额度不足和网络错误显示明确提示，无旧结果替代。
