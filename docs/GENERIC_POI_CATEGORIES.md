# 經停用途應由 Agent 映射為通用地圖類別

## 本次問題

記錄 `20261005T103238-2c091635` 中，用戶已說明“我途中要先去加個油”，模型設定必須經停，卻將 `poi_category` 與 `poi_name` 都置為空。原模型只允許 cafe/restaurant/hospital/bakery 四種類別，解析器隨後直接詢問 `poi_name`，網頁又退回了技術字段提示。未查詢地圖就把類別覆蓋不足當成用戶缺少地址。

## 處理

保留同一個 `search_pois` 工具，以受控的 OSM `key:value` 類別表示需求。可使用 amenity、shop、leisure、tourism、healthcare 五類鍵及合法類別值；類別值不再是四項封閉枚舉。模型根據用途選擇標籤，工具在真實道路採樣位置查詢，逐個核對返回標籤，後續繼續計算經停候選的真實路線和繞行時間。兼容已有麵包店等歷史記錄。

例如加油使用 amenity:fuel、超市使用 shop:supermarket；這只是類別格式示例，不增加加油站專用工具或預設門店地址。查詢範圍、最多五個採樣點、候選數量與擴展預算保持受限。非法鍵值不進入外部查詢；空結果不能被當成已找到地點。

必須經停但遺漏名稱和類別時，讓模型修正提取，不直接結束為缺少地址。類別任務仍禁止向用戶要求挑選門店或提供門店地址。原文確實未說明經停用途時才需要澄清。

用戶沒有給出停留時間時，仍詢問個人安排。不能用“加油通常需要若干分鐘”冒充用戶確認，尤其在有硬到達時限時。營業、燃料兼容性、現場服務等不因類型標籤匹配就自動通過。
