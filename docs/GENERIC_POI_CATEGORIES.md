# 经停用途应由 Agent 映射为通用地图类别

## 本次问题

记录 `20261005T103238-2c091635` 中，用户已说明“我途中要先去加个油”，模型设定必须经停，却将 `poi_category` 与 `poi_name` 都置为空。原模型只允许 cafe/restaurant/hospital/bakery 四种类别，解析器随后直接询问 `poi_name`，网页又退回了技术字段提示。未查询地图就把类别覆盖不足当成用户缺少地址。

## 处理

保留同一个 `search_pois` 工具，以受控的 OSM `key:value` 类别表示需求。可使用 amenity、shop、leisure、tourism、healthcare 五类键及合法类别值；类别值不再是四项封闭枚举。模型根据用途选择标签，工具在真实道路采样位置查询，逐个核对返回标签，后续继续计算经停候选的真实路线和绕行时间。兼容已有面包店等历史记录。

例如加油使用 amenity:fuel、超市使用 shop:supermarket；这只是类别格式示例，不增加加油站专用工具或预设门店地址。查询范围、最多五个采样点、候选数量与扩展预算保持受限。非法键值不进入外部查询；空结果不能被当成已找到地点。

必须经停但遗漏名称和类别时，让模型修正提取，不直接结束为缺少地址。类别任务仍禁止向用户要求挑选门店或提供门店地址。原文确实未说明经停用途时才需要澄清。

用户没有给出停留时间时，仍询问个人安排。不能用“加油通常需要若干分钟”冒充用户确认，尤其在有硬到达时限时。营业、燃料兼容性、现场服务等不因类型标签匹配就自动通过。

## 验证

214 项测试通过，覆盖六类开放类别、真实标签协议过滤、非法查询拒绝、缺失类别回到模型、多个经停候选算路及阻止不必要的用户选店。

在真实浏览器用原始需求重新提交，生成 `20261005T103724-98c6262a`：模型正确返回 `amenity:fuel`，原文依据为“我途中要先去加个油”。页面显示由系统搜索沿途加油站，唯一澄清为停留时间，未要求加油站名称或地址。未替用户填写停留时间；尚未验证该请求的真实地点解析、加油站查询及最终路线。

标签依据：[OSM amenity](https://wiki.openstreetmap.org/wiki/Key:amenity)、[OSM shop](https://wiki.openstreetmap.org/wiki/Key:shop)、[加油站标签](https://wiki.openstreetmap.org/wiki/Tag:amenity=fuel)。地图类型覆盖、模型映射及数据新鲜度仍有边界，不承诺覆盖所有自然语言用途。
