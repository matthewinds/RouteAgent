# 通用地點查詢與覆蓋邊界

用戶要求：不能按“這次缺什麼就補一個專用工具”修補；應讓地點查詢適用於新的公司、品牌、樓宇和別名。此原則已寫入項目 `AGENTS.md`。

## 已實現

Agent 使用同一個 `resolve_place` 接口，根據查詢結果選擇名稱／別名、地址或數據來源。沒有 TikTok 地址表，也沒有針對某家公司增加工具。

- `source=map` 查詢實際 Pelias 地圖地址庫。保留嚴格地點匹配，避免把“Singapore office”返回的其他辦公室當成目標公司。
- `source=registry` 查詢 GLEIF 的真實新加坡法人記錄，取其總部／登記地址，再通過地圖服務定位。它是數據來源適配器，不是辦公室知識表。公司關聯和地圖座標分別保留來源證據。
- 查詢為空後把結果反饋給 Agent，允許換查詢或來源，而不是自動結束並要求用戶重填已給出的目的地。
- 用戶只是在重試失敗查詢時，新查詢不會被上次保存的搜索詞覆蓋。已經確認某個地圖候選時，仍復用原查詢和來源來核對地點身份。
- 公司來源的地址一律要求確認，顯示地址來源鏈接，並註明總部／登記地址不一定是用戶的實際辦公地點，地圖僅定位樓宇／街道，未核實樓層及入口。
- 泛指沿途店鋪仍走自動 POI 搜索和候選比較，不轉為公司或門店地址確認。

接口來源定義見 [GLEIF 官方 API 說明](https://www.gleif.org/en/lei-data/gleif-api/)。該來源只覆蓋其法人記錄，不是完整的公司辦公室目錄；來源沒有記錄時不生成地址。

## 為什麼不能承諾完全識別

語義理解與實際數據覆蓋是兩個問題。LLM 可以改寫查詢和決定下一次查什麼，不能補造地圖未收錄的辦公室，也不能知道“家”“我的公司”等私人位置。同名分店、搬遷或不同辦公樓也需要確認。

要顯著擴大商業 POI 和自然語言查詢覆蓋，應選擇成熟的地點搜索服務作為通用檢索源，再由同一個接口返回候選。例如 [Google Places Text Search](https://developers.google.com/maps/documentation/places/web-service/text-search) 支持文本地點、地址和商業場所查詢，但需要服務配置；項目尚未接入，不能把未來能力作為本次驗收結果。集成時還需處理地圖展示與數據保存：[Google Places 官方政策](https://developers.google.com/maps/documentation/places/web-service/policies) 對其地圖展示及緩存有要求，不能直接將其結果長期存入現有記錄並畫在 OSM 地圖上。

更完整的數據源能減少逐案修補，但任何來源都有覆蓋和新鮮度限制。最終行為應是“通用檢索、改寫與重試、來源核驗、必要時確認”，而不是“保證任何輸入都能識別”。

## 通用網頁檢索與來源核驗（2026-10-05）

新的失敗記錄 `20261005T105456-316dc95d` 已試過英文別名與 GLEIF，但所有來源為空，Agent 隨後要求用戶重填已經給出的“新加坡 OpenAI 的公司”。這說明地圖和 LEI 登記覆蓋不足；先前的修復沒有形成完整的商業辦公室檢索能力。

用戶選擇接入通用網頁檢索，並在本地配置了 Tavily 憑據。`resolve_place` 仍是統一接口，現在支持 `source=web`，分兩階段：

1. 根據 Agent 選擇的關鍵詞調用 Tavily，返回有來源 URL、實際網頁內容、文檔 ID 和檢索證據的有限文檔集。未配置、限流、權限或來源讀取失敗保留獨立錯誤，不能冒充“沒有地點”。
2. Agent 從原文識別公司及辦公樓，提供文檔 ID、公司名、地點名和準確引用。後端校驗引用確實存在且包含對應名稱，再交給 Pelias 定位。座標仍來自地圖服務；樓內花園等附屬地點在有完全同名辦公樓時被過濾。所有公開來源線索需要確認實際目的地，不證明樓層、入口、當前租戶或用戶的辦公地點。

網頁內容是數據，不是指令。擬搬遷地點、活動場地、同名法人和登記地址不能被模型直接認定為辦公室。不得通過模型生成引用、座標或品牌地址表彌補缺失數據。原文引用核驗失敗會回到 Agent 重試。

檢索記錄保留逐次查詢與來源的結果，避免最後一次空查詢覆蓋全部歷史。用戶已提供目的地時，未查詢就要求重填會被拒絕；確實沒有候選時說明已嘗試的來源與配置／覆蓋缺口，替代籠統的“要去哪裡”。已有起終點、十分鐘停留和偏好仍通過澄清延續。

Tavily 憑據只在本地 `.env` 的 `TAVILY_API_KEY` 中配置，使用後端 Authorization header，不寫入工具參數、請求正文或緩存。協議依據：[Tavily Search 官方文檔](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

真實瀏覽器記錄 `20261005T111016-96678fbd`：Agent 自動嘗試 map、registry、web；網頁引用第一次未通過核驗後，自主修正為實際報道原文，生成唯一的 `OpenAI · CapitaSpring, Raffles Place, Singapore` 候選，附 [Business Times 來源](https://www.businesstimes.com.sg/property/openai-steps-singapore-footprint-talks-lease-100000-sq-ft-shaw-tower)。記錄含實際 Tavily 和 Pelias 響應證據，保留 600 秒加油停留，只詢問 `destination_place_id`，不再要求用戶手動提供地址。沒有替用戶確認辦公室，也未繼續生成這次行程的最終路線。

同一辦公地點及搬遷討論也見 [JLL 2026-09-28 新聞稿](https://www.jll.com/en-sea/newsroom/cbd-office-tightness-drives-another-quarter-of-rental-growth-as-vacancy-hits-near-three-year-low)。這是公開線索，不是當日辦公室入口核驗。

該鏈路通用於新公司與樓宇。對於數據不公開、來源錯誤或搬遷未更新的地點仍有覆蓋邊界。網頁檢索 API 本次已實際驗證，不代表能保證識別所有公司辦公室。

## 研究、審閱與候選選擇（本輪通用修復）

`resolve_place` 現在區分研究階段和提交候選階段。模型調用默認 `present_candidates=false`，先得到真實候選名稱、類型、區域與來源，仍可自主改寫別名、繼續搜索或換來源。之後用同一角色曾返回的 `candidate_ids` 提交最多五個相關候選，由用戶選擇；可用 `reject_candidate_ids` 排除無關結果。不是每得到一批地圖結果就立即結束並把附近所有設施都交給用戶判斷。

候選與起點／終點分別綁定，不能用另一角色、任意 POI 或生成 ID 代替。每個候選保存實際搜索來源、關鍵詞及網頁證明，確認後重放所選候選自己的查詢；後續空查詢不會覆蓋先前有效候選的來源。公開來源證明仍需再次核驗。已有未排除候選時禁止要求重填原地點；無候選且 Tavily 已配置時，在請求補充描述之前必須嘗試網頁來源。真正無關的候選可以排除，避免被迫選擇錯誤地點。

起終點在提取工具的 schema 中要求明確提供（缺失時可為 null），並標明“名稱不熟悉不等於未提供地點”。提取修復不能丟失已給出的地點描述。產品候選表列出實際名稱、地址或區域與來源，別名／拼寫／描述等匹配理由標明是 AI 的解釋，最終地點仍由用戶確認。

真實通用檢索迴歸：未添加地點專用規則，Agent 將“新加坡藝術科學博物館”匹配為 `ArtScience Museum, Bayfront Subzone, Singapore`，將“南洋理工大學”匹配為 `Nanyang Technological University, Murai, Singapore`，並各自審閱後提交一個相關候選。記錄分別為 `outputs/20261005T152342-7ff8ad4c/result.json` 和 `outputs/20261005T152342-b8c34a85/result.json`。它們驗證真實名稱檢索與候選提交流程，不代表路線或所有私人地點都可覆蓋。環球影城、Hotel 1900 和 LTA 的本輪故障與完整行程迴歸另見 [地點提取與 LTA 展示修復](ENDPOINT_EXTRACTION_LTA_FIX.md)。

命名的業務經停也通過 `search_pois search_names` 接受同一品牌／分店的語言或拼寫假設，原始 `poi_name` 不改寫。OSM 的真實 `name:*`、`brand:*` 語言名稱和類別參與核對，模型生成的別名不寫入 `Place.names`；`Place.names` 僅保存來源名稱。最終名稱檢查核對實際地圖名稱，並保留原始要求及別名解釋；通用類別經停不允許被別名機制改成指定品牌，不要求用戶填寫具體門店地址。原始名稱、查詢假設和實際門店 ID 保留在搜索記錄中。

最終完整迴歸為 300 項通過，包含中文品牌與英文地圖名稱的經停查詢、真實多語言名稱讀取，以及原始二十分鐘停留和其他約束不被改寫。

最終網頁原始描述迴歸：`outputs/20261005T154422-924111f6/result.json` 保留“環球影城”，經真實名稱檢索和 AI 相關性審閱後僅提交 `Universal Studios Singapore, Sentosa, Singapore` 候選，網頁提供選擇並展示來源；沒有要求重寫起點。
