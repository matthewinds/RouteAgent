# 按完整需求比較組合行程

本輪修復對應“系統臨時選了步行後不能換方式，公共交通不能經過郵局／麵包店”的問題。

- 用戶未指定方式時，`TravelRequest.mode` 保持為空。`choose_mode` 只記錄臨時探索依據；`plan_candidates` 可比較步行、公交／地鐵／步行組合，以及用戶已確認可以使用車輛的自駕。最終方式來自選中的完整候選。
- 所有候選遵循同一份用戶約束。新方式的首次探索不算重規劃，已有合格路線不阻止探索其他方式；同一方式的重規劃仍有驗證與次數限制。
- 公共交通業務經停逐段查詢。後半程查詢時間至少為實際服務到店時刻加用戶確認的停留，並向上對齊 OneMap 的分鐘精度；完整總時間包含等待、換乘和停留。分次查詢的票價不能相加冒充一體化換乘費用。
- `get_transit_hubs` 查詢真實 OneMap MRT／LRT 或公交站點；Agent 根據失敗原因決定是否使用。`plan_candidates` 接受真實站點 ID，調用實際步行路線和公共交通服務進行起點／終點接駁，不固定站名或地址。
- OneMap 返回跨站點換乘而缺少步行段時，查詢真實步行服務並驗證能否趕上後續班次；步行距離計入總上限。不滿足銜接時間的候選被排除。對於同一服務節點的地圖線條偏移，核對站點、服務證據與時刻，不補畫假連接。
- 天氣排序加入服務步行時間、候車／換乘等待和未核實遮蔽的停留。它是保守的潛在暴露參考，不是實際淋雨概率或有頂通道證明。
- OneMap 的標準“未找到路線”響應與接口故障區分；服務未完成且已查詢方式不滿足約束時，不能宣稱所有交通組合無解。無效的一條接口候選不抹掉其他有效候選，比較缺口仍明確顯示。
- 2026-10-06 修復經停批次丟失成功結果：每個門店／站點組合分別記錄失敗，無路線或無效響應繼續其他組合；服務整體故障或預算邊界停止當前批次時，已取得的完整候選仍保留。經停後的某個出發時刻失敗也不能抹掉其他已銜接成功的行程。
- 有效的 OneMap 純步行短程可以與另一段公交／地鐵組合，仍核對實際幾何、時刻和停留。損壞的幾何或時刻不能降級冒充有效步行返回。
- 檢查狀態按各交通方式的實際候選記錄。空／失敗批次可以直接改用新的真實組合；一條合格步行路線不阻止公交重規劃，同一方式的合格路線也不阻止在有限預算內改善偏好。重複組合不重查；每個方式仍最多追加兩輪。擴大門店搜索需要先檢查已生成的候選，但不再要求全部失敗。
- 候選搜索預留 35 秒及 8 次外部請求，用於必要證據檢查和完成推薦；達到邊界明確記錄有限搜索，不承諾預留足夠應對所有外部服務故障。網頁可展開查看未參與比較的組合。
- 未指定方式時，沿途 POI 工具從實際可用的步行、公共交通及已確認可自駕的參考路線上搜索；不依賴 Agent 先調用某個比較工具，也不只取首個方式的全部門店。不同方式的結果交錯合併、去重後執行數量上限，查詢失敗單獨保留。
- 網頁顯示完整分段方式、經停行程總時間、步行和候車換乘等待；初步起終點參考與完整經停比較分開。

真實接口核對：本地新配置令牌已成功請求 OneMap，並取得真實公交、軌道分段及時刻和票價。對此前頁面解析的 ONE°15 Marina Sentosa Cove 起點和 Centennial Tower 終點，測試明日 08:00 出發，通過實際站點檢索與步行接駁取得約 83 分鐘的步行＋地鐵候選，基礎方式、時序和連接檢查通過。它不是對用戶家庭位置的進一步確認，也未包含郵局停留；完整業務經停以網頁迴歸結果為準。
