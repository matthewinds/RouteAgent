# 现在出发行程的交通补查与估计

问题记录 `outputs/20261005T114302-796a3eff/result.json` 中，交通只读取了六页、3000 条速度记录；分页时限耗尽后，事故查询也没有机会执行。第二次 `get_traffic` 直接复用已有结果。候选路况覆盖分别只有约 22%、15%、6%，但原评分直接比较这些路线各自已观测部分的拥堵比例，不能代表全程。

修复：

- 同一工具增加 `continue_collection=true`，继续读取上次未取得的分页，而非反复读取第一页。每次仍受时间和请求预算控制，Agent 最多两次补查。已读取完整时停止。过期分页不能作为有效续查起点。
- 事故查询有独立的短时查询机会，避免速度分页占满时限后直接被跳过。所有查询仍共用整体预算。
- 同一批速度数据复用空间索引，避免为每条候选重复构建。
- 局部路况给出单独的估计字段。计算为“已匹配路段的 LTA 速度时间 + 未匹配距离占比乘以 OSRM 基础时间 + 已确认停留及停车预留”。按距离分配基础时间是一项明确的估计假设；不填补观测、不改变完整时间字段，不据此把到达时限检查改成通过。证据过期时清除估计及拥堵比较值。
- 全程拥堵比例的可知区间为 `[覆盖率 × 已观测拥堵比例, 覆盖率 × 已观测拥堵比例 + 未覆盖比例]`。排序使用区间上界和覆盖不确定性，避免将未观测道路当成畅通。
- “现在出发”是系统动态默认值。后端记录其来源；确认停留、确认地点以及同文重新规划不会封存该默认时间。用户原文指定或主动确认的出发时间仍保留。
- 天气参数接受与路线检查相同规模的候选 ID，查询坐标仍按既有有界批次处理。

LTA 官方文档说明响应最多 500 条，后续通过 `$skip` 获取；速度数据的道路范围是高速和主干道。全部分页读完不能说明所有路线道路都被观测。[API 文档](https://datamall.lta.gov.sg/content/dam/datamall/datasets/LTA_DataMall_API_User_Guide.pdf) · [数据范围](https://datamall.lta.gov.sg/content/datamall/en/search_datasets.html)

测试覆盖续查位置、完成后的停止、事故查询机会、补查次数、局部时间计算与硬约束隔离、过期撤销、覆盖率不同的排序、默认时间刷新与指定时间保留，以及页面估计标签。测试不作为真实 API 连通性证明；网页另行实测。

网页实测记录：`outputs/20261005T115614-5ea9eaf7/result.json`。Agent 发起两次续查，取得 20 页、10000 条速度记录和 7 条事故记录；事故分页完整，速度分页仍有后续。23 条真实路线候选中，第一参考方案约 47% 驾车距离匹配有效路况，部分路况估计约 30.0 分钟。出发时间为本次执行的 19:56，来源为 `default_now`，保留 600 秒经停且没有再次询问地址。全程到达时限、避堵和设施遮蔽仍没有足够证据，结果保持参考状态。
