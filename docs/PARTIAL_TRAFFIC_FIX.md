# 現在出發行程的交通補查與估計

問題記錄 `outputs/20261005T114302-796a3eff/result.json` 中，交通只讀取了六頁、3000 條速度記錄；分頁時限耗盡後，事故查詢也沒有機會執行。第二次 `get_traffic` 直接複用已有結果。候選路況覆蓋分別只有約 22%、15%、6%，但原評分直接比較這些路線各自已觀測部分的擁堵比例，不能代表全程。

修復：

- 同一工具增加 `continue_collection=true`，繼續讀取上次未取得的分頁，而非反覆讀取第一頁。每次仍受時間和請求預算控制，Agent 最多兩次補查。已讀取完整時停止。過期分頁不能作為有效續查起點。
- 事故查詢有獨立的短時查詢機會，避免速度分頁佔滿時限後直接被跳過。所有查詢仍共用整體預算。
- 同一批速度數據複用空間索引，避免為每條候選重複構建。
- 局部路況給出單獨的估計字段。計算為“已匹配路段的 LTA 速度時間 + 未匹配距離佔比乘以 OSRM 基礎時間 + 已確認停留及停車預留”。按距離分配基礎時間是一項明確的估計假設；不填補觀測、不改變完整時間字段，不據此把到達時限檢查改成通過。證據過期時清除估計及擁堵比較值。
- 全程擁堵比例的可知區間為 `[覆蓋率 × 已觀測擁堵比例, 覆蓋率 × 已觀測擁堵比例 + 未覆蓋比例]`。排序使用區間上界和覆蓋不確定性，避免將未觀測道路當成暢通。
- “現在出發”是系統動態默認值。後端記錄其來源；確認停留、確認地點以及同文重新規劃不會封存該默認時間。用戶原文指定或主動確認的出發時間仍保留。
- 天氣參數接受與路線檢查相同規模的候選 ID，查詢座標仍按既有有界批次處理。

LTA 官方文檔說明響應最多 500 條，後續通過 `$skip` 獲取；速度數據的道路範圍是高速和主幹道。全部分頁讀完不能說明所有路線道路都被觀測。[API 文檔](https://datamall.lta.gov.sg/content/dam/datamall/datasets/LTA_DataMall_API_User_Guide.pdf) · [數據範圍](https://datamall.lta.gov.sg/content/datamall/en/search_datasets.html)

測試覆蓋續查位置、完成後的停止、事故查詢機會、補查次數、局部時間計算與硬約束隔離、過期撤銷、覆蓋率不同的排序、默認時間刷新與指定時間保留，以及頁面估計標籤。測試不作為真實 API 連通性證明；網頁另行實測。
