# 自驾经停结果修复

本次页面记录显示：用户填写 19:00 出发，LTA 在 19:18 采集；查询的数据不适用于填写的时段。页面却只显示 0% 覆盖和多个采集错误。天气查询还把多个候选坐标合并后截断为前八个，造成后续路线人为缺少天气参考。参考方案前三项均为同一家加油站的相近路径。

修复采用通用机制，不加入公司或加油站地址表：

- 超出实时路况有效窗口的过去出发时间，不查询实时数据来验证历史行程。与预约未来出发一样，明确显示适用范围、基础路线参考和无法验证的条件。保留用户时间，不自动改成次日。
- 天气工具每次最多四批、每批八个真实坐标，按候选补齐采样并复用有效结果。某批失败时保留已成功采样，返回仍缺少覆盖的路线 ID，让 Agent 决定是否继续查询。
- 天气预报可用与上下车、经停、入口是否能避雨分别验证；缺少遮蔽证据时避雨偏好保持未知。
- 参考结果先取不同经停地点的最佳候选，再补同一地点的不同路径。后台仍保留所有候选和排序。
- 保存 OSM 返回的地址和地点来源链接。地址缺失时显示实际地图坐标以区分同名门店，不生成街道地址。
- 页面聚合搜索次数及去重候选数，详细搜索记录放在展开项。旧记录没有地点 ID 时，使用单次最大候选数，避免把重复结果相加。
- 同一输入重新规划保留已确认字段；修改输入时开启新行程。重复选择已确定方式可以继续执行，但仍禁止模型改写已确定方式。

测试覆盖历史时段不发起实时查询、确认信息保留与新行程隔离、天气分批及部分失败恢复、同名地点的来源与地址、参考方案多样性和避雨偏好的证据界限。测试使用模拟服务，真实连通性通过当前网页另行验证。
