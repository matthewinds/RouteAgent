# 自駕經停結果修復

本次頁面記錄顯示：用戶填寫 19:00 出發，LTA 在 19:18 採集；查詢的數據不適用於填寫的時段。頁面卻只顯示 0% 覆蓋和多個採集錯誤。天氣查詢還把多個候選座標合併後截斷為前八個，造成後續路線人為缺少天氣參考。參考方案前三項均為同一家加油站的相近路徑。

修復採用通用機制，不加入公司或加油站地址表：

- 超出實時路況有效窗口的過去出發時間，不查詢實時數據來驗證歷史行程。與預約未來出發一樣，明確顯示適用範圍、基礎路線參考和無法驗證的條件。保留用戶時間，不自動改成次日。
- 天氣工具每次最多四批、每批八個真實座標，按候選補齊採樣並複用有效結果。某批失敗時保留已成功採樣，返回仍缺少覆蓋的路線 ID，讓 Agent 決定是否繼續查詢。
- 天氣預報可用與上下車、經停、入口是否能避雨分別驗證；缺少遮蔽證據時避雨偏好保持未知。
- 參考結果先取不同經停地點的最佳候選，再補同一地點的不同路徑。後臺仍保留所有候選和排序。
- 保存 OSM 返回的地址和地點來源鏈接。地址缺失時顯示實際地圖座標以區分同名門店，不生成街道地址。
- 頁面聚合搜索次數及去重候選數，詳細搜索記錄放在展開項。舊記錄沒有地點 ID 時，使用單次最大候選數，避免把重複結果相加。
- 同一輸入重新規劃保留已確認字段；修改輸入時開啟新行程。重複選擇已確定方式可以繼續執行，但仍禁止模型改寫已確定方式。

測試覆蓋歷史時段不發起實時查詢、確認信息保留與新行程隔離、天氣分批及部分失敗恢復、同名地點的來源與地址、參考方案多樣性和避雨偏好的證據界限。測試使用模擬服務，真實連通性通過當前網頁另行驗證。
