# 預約出行中的重複待核實提示

## 原因

本次記錄 `20261005T101025-9e4a7da0` 的五項檢查中，交通方式、分段連接、必經地點和天氣參考通過，只有到達時限缺少證據。基礎總時長為 1274.5 秒，包含用戶確認的 600 秒經停；一小時到達窗口剩餘約 38.8 分鐘。這個餘量不是交通延誤預測。

出發時間在下一天。LTA 數據採集時間屬於當前時段，不能驗證預約時段，因此有效交通覆蓋為零。採集同時觸及了獨立分頁預算，但把全部當前數據取完也不能解決未來時間不適用的問題。原頁面重複展示總 ETA 未知、覆蓋率零、費用未知、時間檢查未知及英文條件名，放大了單個硬約束的數據缺口。

## 調整

- 頁面彙總通過數量和具體缺少證據的條件；每個候選顯示自己的檢查狀態。
- 預約駕車方案顯示“當前路況不適用”和“臨近出發時更新”，合併交通提示，並提供有來源的基礎到達時間和時間餘量。
- 使用保存的採集時間判斷舊記錄的交通適用性，避免瀏覽舊結果時改變原因。
- 查詢交通工具時先檢查時段適用性；未來出發不下載無法用於該時段的實時速度數據，說明尚無預測交通時間，並讓 Agent 繼續比較基礎路線與天氣。
- 對自駕避堵偏好增加獨立的軟約束證據檢查。它不應在缺少路況時被默認為已滿足。
- 不把硬約束未知改為通過，不修改歷史規劃記錄，不改變已確認地點或停留時間。

## 驗證

198 項測試通過，包含預約交通不發起外部請求、硬時限仍未通過、避堵證據為軟約束、時間餘量及網頁狀態展示測試。真實瀏覽器保留原行程刷新後，顯示“已通過 4 項檢查；仍有 1 項缺少證據：到達時限”和“38.8 分鐘餘量”。新的避堵檢查會在下一次規劃時生成；現有結果未重新請求模型或地圖服務。
