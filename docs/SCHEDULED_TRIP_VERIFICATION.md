# 预约出行中的重复待核实提示

## 原因

本次记录 `20261005T101025-9e4a7da0` 的五项检查中，交通方式、分段连接、必经地点和天气参考通过，只有到达时限缺少证据。基础总时长为 1274.5 秒，包含用户确认的 600 秒经停；一小时到达窗口剩余约 38.8 分钟。这个余量不是交通延误预测。

出发时间在下一天。LTA 数据采集时间属于当前时段，不能验证预约时段，因此有效交通覆盖为零。采集同时触及了独立分页预算，但把全部当前数据取完也不能解决未来时间不适用的问题。原页面重复展示总 ETA 未知、覆盖率零、费用未知、时间检查未知及英文条件名，放大了单个硬约束的数据缺口。

## 调整

- 页面汇总通过数量和具体缺少证据的条件；每个候选显示自己的检查状态。
- 预约驾车方案显示“当前路况不适用”和“临近出发时更新”，合并交通提示，并提供有来源的基础到达时间和时间余量。
- 使用保存的采集时间判断旧记录的交通适用性，避免浏览旧结果时改变原因。
- 查询交通工具时先检查时段适用性；未来出发不下载无法用于该时段的实时速度数据，说明尚无预测交通时间，并让 Agent 继续比较基础路线与天气。
- 对自驾避堵偏好增加独立的软约束证据检查。它不应在缺少路况时被默认为已满足。
- 不把硬约束未知改为通过，不修改历史规划记录，不改变已确认地点或停留时间。

## 验证

198 项测试通过，包含预约交通不发起外部请求、硬时限仍未通过、避堵证据为软约束、时间余量及网页状态展示测试。真实浏览器保留原行程刷新后，显示“已通过 4 项检查；仍有 1 项缺少证据：到达时限”和“38.8 分钟余量”。新的避堵检查会在下一次规划时生成；现有结果未重新请求模型或地图服务。

目前仍缺少预约时段的交通预测，不能宣称已证明明天准时或避堵。接入这类能力需要评估支持指定出发时间的真实路线服务，而不是增加公司或门店特例。
